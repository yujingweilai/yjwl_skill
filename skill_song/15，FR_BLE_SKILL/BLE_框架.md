# FR801x BLE 框架 Skill

## 适用范围

本 Skill 面向 FR801x SDK 的 `examples/dev1.0/ble_simple_peripheral` 类型工程。默认保持原有 Keil ARMCC 工程框架、SDK 目录关系、启动文件、Scatter 文件、BLE Stack 库和既有接口，不主动迁移到 GCC、重构工程或替换底层架构。

## 核心启动流程

必须保持以下顺序：

```text
芯片启动
→ app_main
→ 用户系统参数配置
→ BLE 初始化前钩子
→ BLE 协议栈初始化
→ BLE 初始化后钩子
→ 创建用户任务
→ 设置设备名、安全参数和 GAP 回调
→ 注册全部 GATT 服务
→ GAP_EVT_ALL_SVC_ADDED
→ 开始广播
```

必须在 `GAP_EVT_ALL_SVC_ADDED` 之后启动广播，不能在服务尚未全部注册完成时广播。连接建立后可交换 MTU、请求连接参数更新；断开后按产品需求重新广播。

## BLE 外设规范

### 设备地址

BLE 地址数据、地址类型和持久化策略必须成套确认。`Public`、`Random Static`、可解析私有地址不能混用规则；修改地址最高位前必须先确认 SDK 对地址类型的要求。

### 广播与扫描响应

修改广播包或扫描响应时，必须重新核对每个 AD 结构的长度字段和实际数据长度，并确认总长度不超过 BLE 规范及 SDK 接口限制。新增服务 UUID、设备名或功率字段时，不得只修改长度字节而不重新计算数组大小。

### GAP/GATT 回调

回调函数必须先检查事件类型、事件参数和连接索引 `conidx`。回调中只做快速、非阻塞的状态处理；传感器读取、LCD 刷屏、音频解码、复杂格式化和大量日志必须通过任务、消息或异步事件执行。

MTU 更新事件只表示协商结果。发送通知、处理写入和拼包时仍必须按实际 MTU、ATT 有效负载、应用缓冲区容量和服务属性长度进行边界检查。

### 服务与绑定

GATT 服务必须先注册并确认完成，再进入可连接广播。Bond 信息地址必须与 Flash 型号、分区配置和 Scatter 布局一致。`gap_bond_manager_delete_all()` 只能作为明确标注的测试行为，不能放在正式产品的正常启动路径中无条件执行。

## 任务与事件

用户任务和音频任务应分别承担按键、音频准备、下一帧、停止等业务。事件处理前必须检查 `param` 和事件参数的有效性，并确认消息参数的生命周期，不得把仅在回调期间有效的指针长期保存。

耗时工作应转移到任务上下文。初始化函数必须明确是否可重复调用，避免重复创建任务、重复启动定时器、重复注册服务或覆盖仍在使用的状态。

## 低功耗规范

启用睡眠前，必须逐项确认 UART、GPIO 复用、定时器、传感器、LCD、I2S、PMU 和 BLE 的睡眠保持及唤醒恢复行为。睡眠前后执行的函数必须按工程约定放入 `ram_code` 段；唤醒后不能假设外设寄存器、中断使能或时钟状态仍然有效，必要配置必须重新执行。

睡眠开关、调试延时和 J-Link 调试窗口必须明确标记为调试配置或产品配置。开启低功耗后，必须验证广播、连接、音频和传感器功能，而不是只验证编译通过。

## 日志规范

新增关键逻辑必须输出英文日志，统一使用 `\r\n`，建议使用 `[BLE]`、`[GAP]`、`[GATT]`、`[PMU]`、`[AUDIO]` 等模块前缀。日志应包含动作、结果、错误码、连接索引、断开原因、MTU 或连接参数等关键上下文。

高频日志必须可关闭或降级，不能放大 UART 占用、实时处理延迟或功耗。错误路径必须有可定位日志，例如广播启动失败、服务注册失败、内存不足和唤醒恢复失败。

## 修改验收

- 构建工具仍为工程实际使用的 ARMCC/Keil，未误引入 GCC 专用配置。
- 服务注册完成后才开始广播，连接和断开事件流程完整。
- 广播、扫描响应、MTU、连接参数和连接索引均有边界检查。
- 回调没有新增阻塞或不可控耗时操作。
- 睡眠前后 RAM 代码、外设恢复和中断恢复路径明确。
- 新增函数包含中文注释，说明函数名称、参数、返回值和作用。
- 新增关键路径包含英文日志，且没有引入未声明变量或函数。
