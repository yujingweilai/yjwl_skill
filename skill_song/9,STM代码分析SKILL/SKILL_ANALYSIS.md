# ST `SKILL.md` 分析总结

## 1. 文档定位

- 对象：`st/SKILL.md`
- 基准方向：单核、裸机、非阻塞、`switch-case` 状态机
- 目标平台：STM32 / 32位单片机（裸机，非 FreeRTOS）
- 当前结论：文档已从“带一定工程分层的通用状态机”收敛为“单定时器节拍 + 任务表回调 + 主循环轮询 + 生命周期状态机”的实用方案，更贴近裸机单核项目。

## 2. 与目标约束的匹配度

### 2.1 核心思想匹配

- 已覆盖“离散状态 + `on_enter/on_run/on_exit` 生命周期 + 显式状态切换”。
- 已明确“主循环运行”“禁止 `goto`”“不使用消息队列”。
- 已把任务执行方式改为“定时器打点 + 任务表 + 主循环轮询派发”，符合非阻塞裸机设计。
- 评价：与当前目标约束高度一致。

### 2.2 调度方式匹配

- 已不再依赖 `HAL_Delay(1)` 维持节拍。
- 已采用 `Task_Marks_Handler_Callback()` 在定时器中断中打点。
- 已采用 `Task_Pro_Handler_Callback()` 在主循环中遍历任务表并调用 `task_hook`。
- 评价：调度方式已经明显优于原来的阻塞延时版本。

### 2.3 状态机职责匹配

- `Screen_OnRun()` 只负责状态判断与切换，不再直接承担所有周期任务。
- 任务调度与状态切换职责已经拆开，层次更清楚。
- 状态切换通过统一入口 `Screen_ChangeState()` 处理，避免转移逻辑分散。
- 评价：比原版本更适合维护，也更容易扩展。

### 2.4 简单性匹配

- 虽然是 STM32 版本，但已经尽量收敛到“1个定时器 + 1个任务表 + 1个主循环 + 1个状态机组件”的简单结构。
- 仍保留一定目录分层，适合 32 位机项目继续扩展。
- 评价：在 32 位平台上属于“兼顾规范与简单”的折中方案。

## 3. 当前版本的技术亮点

- 非阻塞性更强：移除了 `HAL_Delay(1)`，主循环响应更及时。
- 结构更清晰：中断只打点，主循环遍历任务表，状态机只做切换判断。
- 可维护性更好：任务调度与状态切换分离，便于排查时序问题。
- 兼容单核裸机：不依赖 RTOS，不需要消息队列，任务遍历顺序可控。
- 可扩展性保留：在不改变主架构的前提下，仍可增加任务与状态。

## 4. 当前版本的优缺点

### 4.1 优点

- 比阻塞延时版本更符合实时轮询思想。
- 任务通过表驱动统一管理，调用路径集中，扩展新任务更方便。
- 状态机生命周期完整，便于后续统一风格。
- 对 STM32 这类 32 位单片机来说，代码复杂度仍然可控。

### 4.2 缺点

- 虽然状态机仍保持 `switch-case`，但调度层引入函数指针后，需要注意回调函数命名和注册一致性。
- 相比 STC 极简版，目录结构仍偏工程化，对超小项目略显重。
- 若后续继续增加很多任务，任务表虽然更容易扩展，但也要控制回调数量与周期配置的可读性。

## 5. 风险点

- 若某个 `task_hook` 内部仍然包含阻塞等待，整个“非阻塞轮询”优势会失效。
- 若任务执行时间差异较大，排在后面的任务会出现抖动。
- 若 `g_sys_tick` 被多个上下文访问，需要注意中断与主循环的数据一致性。
- 若后续重新引入复杂事件总线或分散状态切换入口，结构会再次变重。

## 6. 优化建议

- 保持任务表顺序固定，并为每个任务设定最大单次执行时间。
- 对 `g_sys_tick` 相关超时判断补充统一封装，减少重复写法。
- 给每个状态增加进入时间、超时条件、恢复条件的统一说明。
- 若任务数量继续增加，可按模块拆分任务回调，但仍保持统一任务表注册。
- 对错误状态补充恢复路径和故障码说明，增强工程可落地性。

## 7. 适用场景评估

- 适用于：屏幕流程、通信流程、采样控制、简单电机状态管理、外设轮询驱动。
- 适合：单核、裸机、无消息队列、强调可读性的 32 位 MCU 项目。
- 不建议直接用于：高并发强实时系统、需要复杂优先级调度的任务体系。

## 8. 综合结论

- 当前 `st/SKILL.md` 已经完成从“阻塞轮询示例”到“非阻塞定时器节拍 + 任务表回调架构”的升级。
- 该版本更适合作为 32 位裸机状态机参考模板，尤其适合单核、简单控制、无消息队列的项目。
- 如果后续目标继续强调“更少抽象、更少层次”，则可以再向 `stc` 的极简风格靠拢；如果目标是中型工程扩展，则当前版本已经比较平衡。
